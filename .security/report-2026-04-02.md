## Couche 4 — Raisonnement IA

### Findings Actionnables

#### 1. MEDIUM-HIGH: Provision credits charge replay
Un user pourrait appeler `/provision-credits` plusieurs fois et re-claim le meme paiement Stripe si le charge est dans les 35 derniers jours. Il manque un tracking des charges deja reclamees.

**Fix:** Ajouter une colonne `last_provisioned_charge_id` dans `user_profiles` ou une table `claimed_charges`.

#### 2. MEDIUM: Credits non reset au downgrade
Quand un user cancel son abo, le `plan` passe a "free" mais `points_balance` reste intact. Le user garde ses credits restants.

**Fix:** Ajouter `points_balance = 0` (ou prorata) dans le handler de cancellation du webhook Stripe.

#### 3. LOW-MEDIUM: Fetch interceptor actif en production
Le debug fetch interceptor (`window.fetch` override) est toujours actif. Un user avec `?debug=1` peut voir les requetes API dans le DOM.

**Fix:** Wrapper dans `if (import.meta.env.DEV)`.

#### 4. LOW-MEDIUM: Double-click sur Generate
Le check `isRunning` est asynchrone — 2 clics rapides peuvent passer avant le state update. Le backend RPC protege (row lock), mais le frontend devrait aussi debounce.

**Fix:** `btn.disabled = true` synchrone ou `useRef` pour le lock.
